# Tauri 客户端 MVP 设计文档

## 目标

在 `D:\CodexProjects\workflow-manager-client` 新建一个轻量桌面客户端，用 Tauri + Rust 提供本地项目能力，用 React/Vite 提供深色 CLI 终端风界面。客户端解决 web 版无法自然添加本地项目、读取代码上下文、执行测试命令和沉淀本地规则的问题。

## MVP 范围

第一阶段只做可闭环的本地智能底座：

1. 添加本地项目路径。
2. 扫描文件树并读取代码上下文摘要。
3. 管理多模型 Provider 与角色级 Agent 配置。
4. 运行需求澄清、场景预演、边界探测、质询、红蓝对抗、方案收敛、任务拆解、测试驱动实现的工作流记录。
5. 保存测试结果、失败归因、复盘条目和 AI 工作宪法规则。

暂不做插件市场、分布式 Agent、复杂权限系统和真实自动代码修改的高风险闭环。MVP 先做到“读项目、懂上下文、生成任务和测试闭环计划、记录复盘”。

## 架构

前端使用 React + Vite + TypeScript，保持少依赖。Tauri commands 暴露 Rust 能力：项目扫描、文件读取、配置存储、工作流状态、命令执行占位。Rust 层是可信边界，所有本地文件、命令和密钥访问都必须经过显式 command。

本地数据使用 SQLite 保存项目、文件索引、工作流运行、事件日志、产物、复盘和宪法规则。API Key 不明文进入 SQLite，后续接系统 keychain；MVP 先存 provider 配置和 key 引用名。

## UI

整体参考 Codex 客户端和终端 CLI：深色背景、等宽字体、低装饰、高信息密度。

- 左侧：项目列表、工作流列表、Agent/Provider 设置入口。
- 中间：流程日志终端窗口和底部聊天输入。
- 右侧：当前项目上下文、测试结果、红蓝对抗、宪法规则。
- Agent 管理页：单 Agent 聚焦编辑，不同时铺开所有角色。

## 核心模块

### 项目上下文

项目由路径注册。扫描时跳过 `.git`、`node_modules`、`dist`、`build`、`target`、`.next`、`coverage` 等目录，并限制单文件大小。上下文摘要优先读取项目结构、README、package/Cargo/配置文件、src 文件列表和测试文件列表。

### Provider 与 Agent

Provider 抽象包含 `id`、`kind`、`base_url`、`model`、`api_key_ref`。Agent 绑定角色、provider、模型、temperature、system prompt。首批支持 OpenAI-compatible 抽象，后续映射 DeepSeek、Anthropic、Gemini。

### 工作流

内置角色：管理员、产品、开发、架构师、测试。沿用 web MVP 的方法论提示词：场景预演、边界探测、质询、红蓝对抗、集成测试优先、端到端测试、失败归因和 AI 工作宪法。

状态流：需求输入 -> 澄清 -> 场景预演 -> 边界探测 -> 红蓝质询 -> 方案收敛 -> 任务拆解 -> 测试计划 -> 执行记录 -> 复盘归因 -> 宪法沉淀。

### 测试驱动

第一阶段重点验证三类路径：项目扫描、上下文摘要、工作流状态转换。测试策略以 Rust 集成测试为主，前端补交互测试，后续用 Tauri E2E 验证添加项目到生成任务的完整路径。

## 错误与安全

- 读取路径必须是用户添加过的项目根目录或其子路径。
- 扫描必须有忽略规则、大小限制和错误记录。
- 命令执行默认禁用，启用时必须显示命令、工作目录和风险。
- API Key 不进入日志、不进入事件、不明文进入数据库。

## 第一阶段完成标准

1. 桌面客户端可启动。
2. 可以添加 `D:\CodexProjects\workflow-manager-mvp` 作为项目。
3. 可以展示文件树和上下文摘要。
4. 可以配置 mock/OpenAI-compatible provider 元数据。
5. 可以创建一次工作流运行，输出需求拆解、场景预演、边界清单、测试计划和复盘占位记录。
6. Rust 核心测试和前端构建通过。
